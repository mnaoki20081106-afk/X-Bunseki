## Grokに向いていること / 向いていないこと

Grokの唯一かつ決定的な強みは、**X(Twitter)のリアルタイム投稿を実際に検索して読めること**です。
逆に言えば、そこ以外での優位性はありません。

| 頼むべき | 理由 |
|---|---|
| ✅ 今のXで実際に何が伸びているかの調査 | Grokだけが実データを見に行ける |
| ✅ X検索クエリを実際に叩いて検証 | 結果を確認できる |
| ✅ こちらが渡した実測ログの統計分析 | 数値の傾向を読む用途に適する |
| ❌ データを見せずに「閾値はいくつが良いか」 | 誰にも答えられない。必ず推測になる |
| ❌ コードの書き換え | 実行環境が無いので検証できない |

**❌の使い方をすると、以前と同じことが繰り返されます。**
`detector.py` のコメントには「Grokの第3提案を反映」「Grokとの複数回のレビューを経て再設計」
と4回分の調整履歴が残っていますが、その結果が
**49回の実行で通知が6回しか出ないシステム**でした。
データを見せずに数字を聞けば、Grokは丁寧な口調で推測を答えます。それを実装しても当たりません。

以下のプロンプトはすべて、**実データを渡す**か**Grokにしかできない調査を頼む**形にしてあります。

## プロンプト③ バズる投稿の初動パターンを調べる

**いつ**: 運用開始から3日ほど経ってから。

**なぜ**: 現在のスコア配点(伸び率40/加速度15/議論量15/保存率10/拡散率10/関連度10)は
**構造的に妥当な推定値ですが、実データで検証したものではありません。**
「実際にバズった投稿はどう数字が動いたのか」が分かれば、配点を事実に基づいて決められます。

<details open>
<summary><b>▼ ここから下をすべてコピーしてGrokに貼る</b></summary>

```
あなたはXの投稿を実際に検索・観察できます。実際に調べた投稿を根拠に答えてください。
推測で答える部分には【推測】と明記してください。

────────────────────────────────
■ 前提(あなたは初見のはずなので説明します)
────────────────────────────────

私はXの日本語投稿を15分おきに自動観測し、「これから伸びる投稿」を早期に検知して、
TikTokでスクープ速報・解説動画を作っています。

観測できる数値は、いいね数・リポスト数・返信数・ブックマーク数・表示回数の5つです。
同じ投稿を15分おきに見るので、前回との差分から次の2つを計算しています。

  いいね/分 = (今回のいいね − 前回のいいね) ÷ 経過分
  加速度   = 直近区間の速度 ÷ その前の区間の速度   (1.0超なら加速中)

そして次の6項目に重みを付けて、0〜100点の総合スコアを出しています。

  伸び率 40点  … いいね/分(対数スケール。120いいね/分で満点)
  加速度 15点  … 加速度2.0倍で満点
  議論量 15点  … 返信 ÷ いいね が10%で満点
  保存率 10点  … ブックマーク ÷ いいね が15%で満点
  拡散率 10点  … リポスト ÷ いいね が25%で満点
  関連度 10点  … 監視キーワードへの当たり具合
```
